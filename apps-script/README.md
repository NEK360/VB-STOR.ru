# Серверная часть: регистрация, вход и заказы (Google Apps Script + Google Таблица)

Корзина, оформление заказа, регистрация и «Мои заказы» на сайте работают через **ваш существующий
Google Apps Script** — тот самый, что уже отдаёт каталог (`?action=catalog`). Каталог и его формат **не
меняются**. Сюда добавляется только то, чего в скрипте не хватало: пользователи и заказы.

> В репозитории нет исходников вашего скрипта (он живёт в Google), поэтому его нельзя обновить
> автоматически. Ниже — 3 коротких шага. Пока они не выполнены, каталог, корзина, избранное, промокод и
> оформление работают, но **регистрация, вход и создание заказа показывают сообщение «Сервис временно
> недоступен»** (сайт не ломается и ничего не теряет).

## Что понадобится

| Файл | Нужен? | Что делает |
|---|---|---|
| `VBStoreApi.gs` | **да** | регистрация, вход, создание заказа, история заказов |
| `VBStoreNotify.gs` | нет | письмо на почту о каждом новом заказе (запросит доп. разрешение на отправку почты) |

## Шаг 1. Добавьте код в проект

1. Откройте проект Apps Script, который отдаёт каталог (из Google Таблицы: **Расширения → Apps Script**).
2. Слева у «Файлы» нажмите **＋ → Скрипт**, назовите `VBStoreApi`, вставьте всё содержимое `VBStoreApi.gs`.
3. *(по желанию)* так же добавьте `VBStoreNotify.gs`, если хотите получать письма о заказах. В нём в начале
   файла укажите свою почту (`OWNER_EMAIL`).

Если скрипт создан **не из таблицы** (отдельный проект на script.google.com), в начале `VBStoreApi.gs` в
`CONFIG.SPREADSHEET_ID` впишите ID таблицы (длинная строка между `/d/` и `/edit` в её адресе).

## Шаг 2. Подключите к `doPost`

В вашем проекте найдите функцию `doPost`.

**Если её нет** (скорее всего) — добавьте целиком, например, в конец главного файла:

```js
function doPost(e) {
  var vbResponse = vbStoreHandlePost_(e);   // заказы, регистрация, вход
  if (vbResponse) return vbResponse;
  return ContentService
    .createTextOutput(JSON.stringify({ ok: false, error: { code: 'UNKNOWN_ACTION' } }))
    .setMimeType(ContentService.MimeType.JSON);
}
```

**Если `doPost` уже есть** — просто добавьте две строки в самое его начало:

```js
var vbResponse = vbStoreHandlePost_(e);
if (vbResponse) return vbResponse;
```

*(необязательно)* в самое начало `doGet` можно добавить проверочный ответ — тогда по адресу
`…/exec?action=vbPing` будет видно, что дополнение подключено:

```js
var vbPing = vbStoreHandleGet_(e);
if (vbPing) return vbPing;
```

`doGet` с `action=catalog` не трогайте — он продолжает работать как раньше.

## Шаг 3. Запустите настройку и опубликуйте новую версию

1. В редакторе выберите функцию **`vbStoreSetup`** и нажмите **Выполнить**. Google попросит разрешения
   (доступ к таблицам) — разрешите. Будут созданы листы **USERS** и **ORDERS** и секретные ключи.
2. Выберите **`vbStoreSelfTest`** → **Выполнить**. В журнале должно быть «Каталог прочитан: строк …».
   Если там ошибка — значит, из вашего `doGet` не получилось прочитать каталог; напишите мне, подскажу.
3. **Начать развертывание → Управление развертываниями → ✎ (изменить) → Версия: «Новая версия» →
   Развернуть.** Адрес веб-приложения **не изменится** — менять его на сайте не нужно.
   (Если создадите *новое* развертывание, адрес станет другим — тогда его нужно заменить в
   `src/lib/config.ts` и `src/lib/api.ts`.)

Проверка: откройте на сайте страницу «Профиль» → «Регистрация», зарегистрируйтесь, оформите тестовый
заказ — в таблице появятся строки в **USERS** и **ORDERS**.

> ⚠️ **Не удаляйте** в «Настройки проекта → Свойства скрипта» значения `TOKEN_SECRET` и
> `PASSWORD_PEPPER`: без них все пользователи потеряют вход. Таблицу с листом USERS не делайте публичной.

## Если на сайте «Не удалось подключиться к серверу»

Это сообщение значит, что браузер не смог прочитать ответ скрипта. К интернету покупателя оно обычно не относится: каталог при этом загружается. Для Apps Script так выглядит ситуация, когда по адресу `/exec` вместо данных отвечает страница ошибки Google.

**Быстрая проверка.** Откройте на сайте страницу `/vb-check.html` (например, `https://ваш-сайт/vb-check.html`) и нажмите «Проверить». Страница отправляет в скрипт те же запросы, что и сайт, и по-русски объясняет, что не так и что сделать. Ничего не записывается: используется запрос «Кто я?» с заведомо неверным ключом. Если проверка красная, скопируйте «Технический отчёт» внизу страницы и пришлите разработчику.

Причины, по частоте:

1. **Не опубликована новая версия.** Адрес `/exec` выполняет последнюю *опубликованную* версию, а не сохранённый код. «Сохранить» и запуск функций в редакторе его не обновляют (поэтому `vbStoreSelfTest` может проходить, а сайт нет). Решение: Начать развертывание → Управление развертываниями → ✎ → Версия: «Новая версия» → Развернуть. Не создавайте «Новое развертывание»: у него будет другой адрес.
2. **Новый адрес не прописан на сайте.** Если новое развертывание всё же создано, его адрес нужно вставить в `src/lib/config.ts` и в `src/lib/api.ts` (в обоих файлах он должен быть один и тот же). Сначала проверьте новый адрес на странице `/vb-check.html`: его можно вставить в поле сверху.
3. **Доступ.** У веб-приложения «Выполнять от имени» — Я, «У кого есть доступ» — Все.
4. **`doPost` не подключён** (шаг 2). Проверка покажет ответ `UNKNOWN_ACTION`.
5. **Нет разрешений.** После добавления кода запустите `vbStoreSetup` в редакторе, подтвердите доступ и опубликуйте новую версию.

**Что смотреть в редакторе.** Раздел «Выполнения» (список слева). После нажатия «Проверить» или попытки регистрации на сайте там должна появиться строка `doPost`. Нет строки: запрос не дошёл до этой версии скрипта. Строка со статусом «Не выполнено»: в ней текст ошибки.

Страница `/vb-check.html` служебная, покупателям она не нужна. Когда всё заработает, файл `public/vb-check.html` можно удалить.

## Если на сайте «Сервер слишком долго отвечает» или «Сервер сейчас занят»

Запрос дошёл до скрипта, но ответ не уложился в 30 секунд (или скрипт сам сообщил, что занят). Сама регистрация лёгкая: обычно это секунда-две.

**Что выяснилось на практике.** Таблица быстрая, а **общую блокировку скрипта** (`getScriptLock`) надолго занимает другой процесс вашего проекта, например синхронизация каталога по триггеру. Раньше регистрация и заказ тоже брали эту блокировку (чтобы не создать два одинаковых номера заказа) и ждали, пока её отпустят. Теперь они берут **отдельную блокировку пользователя** и от вашей синхронизации не зависят. Блокировка документа здесь не подходит: в веб-приложении Google возвращает для неё `null`.

1. Замените весь `VBStoreApi.gs` новой версией из репозитория и опубликуйте новую версию (Начать развертывание → Управление развертываниями → значок карандаша → Версия: «Новая версия» → Развернуть). Адрес не изменится.
2. Запустите в редакторе `vbStoreSelfTest`. В журнале появится строка «Скорость таблицы — …»: время открытия, чтения и записи и состояние **обеих** блокировок до и после чтения каталога. По ней видно, кто держит блокировку скрипта: «ДРУГОЕ выполнение» (триггер) или ваш код чтения каталога (`doGet`). Регистрации и заказам это больше не мешает.
3. Если после обновления всё равно «Сервер сейчас занят», значит, занята именно блокировка пользователя: другой запрос записи или ваш код, который тоже берёт `getUserLock`. Смотрите «Выполнения» и «Триггеры» (значок часов слева).
4. В «Выполнениях» у строки `doPost` в журнале есть строка вида `VBStoreApi register: ok, всего 1850 мс, листы 420 мс, запись 610 мс`. По ней видно, на что ушло время.
5. Страница `/vb-check.html` (шаг 3) измеряет чтение таблицы без записи.

## Письма о новых заказах на почту (необязательно)

Письмо приходит при каждом новом **заказе** (не при регистрации). Чтобы оно работало:

1. Добавьте в проект файл `VBStoreNotify.gs` и в начале укажите свою почту (`OWNER_EMAIL`).
2. Запустите в редакторе функцию **`vbStoreNotifyTest`** (один раз). Google попросит разрешение на отправку писем: разрешите. На почту придёт тестовое письмо «новый заказ №ТЕСТ» (посмотрите и папку «Спам»).
3. Опубликуйте новую версию веб-приложения (как в пункте 1 выше), чтобы разрешение действовало и для сайта.

Если письма не приходят, в «Выполнениях» у `doPost` в журнале будет строка «Не удалось отправить уведомление о заказе: …» с причиной. Сам заказ при этом сохраняется.

## Лист ORDERS — что видите вы

Первые 12 колонок — ровно те, что нужны для работы. Дальше идут `deliveryPrice` и служебные колонки (по ним
сайт показывает «Мои заказы» и не создаёт дубли заказов). В уже существующий лист новые колонки добавляются
справа, остальное не трогается.

| Колонка | Что внутри |
|---|---|
| `orderId` | номер заказа (10001, 10002, …; если у вас уже есть заказы — продолжится после них) |
| `createdAt` | дата и время |
| `userPhone` | телефон покупателя (+7XXXXXXXXXX), берётся из его аккаунта |
| `items` | читаемый список: название, артикул, **размер**, цвет, **количество**, сумма по позиции |
| `total` | итого к оплате, ₽ |
| `promoCode` / `discount` | промокод и скидка в ₽ |
| `deliveryType` | «Пункт выдачи» или «Доставка по России» |
| `deliveryService` | служба: Wildberries, OZON, Яндекс, CDEK, Почта России (для «Доставки по России») |
| `pickupAddress` | выбранный пункт выдачи (для «Пункта выдачи») |
| `paymentMethod` | «Сразу» или «При получении» |
| `status` | статус заказа |
| `subtotal`, `itemsJson`, `requestId` | служебные: сумма без скидки, данные для «Мои заказы», защита от дублей |
| `deliveryPrice` | стоимость доставки: «Бесплатно» (пункт выдачи) или «от 96 ₽» (служба). В `total` **не входит** |

Можно добавлять свои колонки (например, «Комментарий менеджера»): скрипт пишет только в свои колонки, а новую
строку заказа ставит в первую свободную строку **по колонке `orderId`**. Формулы, галочки и заметки в ваших
колонках не затираются и не уводят заказы вниз.

## Стоимость доставки

* **Пункт выдачи** — бесплатно.
* **Доставка по России** — цена «от»: Wildberries от 96 ₽, OZON от 144 ₽, Яндекс от 225 ₽, CDEK от 290 ₽,
  Почта России от 249 ₽. «От» — минимальная стоимость: точную сумму вы подтверждаете с покупателем.
* Покупатель видит стоимость при выборе способа доставки, в итогах оформления, на странице «Заказ оформлен» и
  в «Мои заказы». В **сумму заказа («Итого») она не входит**: это отдельная строка с пояснением.
* В заказ стоимость записывает **сервер** по своему списку (колонка `deliveryPrice`), подменить её с сайта нельзя.
  Она же указана в письме о заказе.
* Цены меняются в двух местах (как промокоды): `CONFIG.DELIVERY_PRICES` здесь **и** `RUSSIA_SERVICE_PRICES` в
  `src/lib/delivery.ts` на сайте.

## Письмо о заказе пришло, а в таблице заказа не видно

Заказ не теряется: письмо отправляется только после того, как запись **проверена** (скрипт читает записанную ячейку
обратно; если записи нет, покупатель получает ошибку, а письма нет). Чаще всего заказ записан, но не там, где вы смотрите.

1. Откройте письмо: в нём есть строка **«Запись в таблице: лист «ORDERS», строка N»** и ссылка на неё.
2. Или найдите заказ вручную: Ctrl+F → номер заказа → **«Искать во всех листах»**.
3. Запустите в редакторе `vbStoreSelfTest`: в журнале строка «Таблица «…», листы: …; лист ORDERS: заказов N,
   последний в строке M…» покажет, в какую таблицу и в какой лист пишутся данные, и предупредит, если есть
   похожий лист (например, `order`).

Типичные причины:

* **Имя листа.** Оно должно совпадать с `CONFIG.ORDERS_SHEET` (`ORDERS`) точно, включая регистр. Если листа с таким
  именем нет, скрипт создаёт новый. Переименовали лист: верните имя `ORDERS` или поменяйте `CONFIG.ORDERS_SHEET`.
* **Другая таблица.** Если в `CONFIG.SPREADSHEET_ID` указан ID, записи идут в ту таблицу, а не в ту, из которой
  открыт скрипт.
* **Фильтр или сортировка** в листе скрывают новые строки (например, фильтр по статусу «Новый» прячет «Ожидает оплаты»).
* **Строка далеко внизу.** В прежней версии заказ ставился под самую нижнюю занятую ячейку листа, и формулы или
  галочки в других колонках уводили его на сотни строк вниз. Теперь строка выбирается по колонке `orderId`.

### Статусы

Сайт ставит только два начальных статуса — это **предложение**, измените в `CONFIG` при желании:

* «**Ожидает оплаты**» — оплата «Сразу» (на сайте нет онлайн-оплаты: вы связываетесь с покупателем и
  согласуете оплату);
* «**Новый**» — оплата «При получении».

Дальше вы меняете статус **вручную в таблице** («Подтверждён», «Отправлен», «Выдан» — любой текст). Покупатель
увидит его в «Мои заказы».

## Что проверяет сервер (клиенту не доверяет)

* телефон берётся из токена сессии, а не из запроса;
* цены, наличие размеров и промокод пересчитываются **по каталогу**: подменить сумму в браузере нельзя;
  если за время оформления цена изменилась — сайт попросит подтвердить новую сумму;
* оплата «При получении» разрешена только для трёх пунктов выдачи Wildberries; для всех остальных
  способов доставки принимается только «Сразу»;
* адрес пункта выдачи и служба доставки должны быть из списка;
* повторное нажатие «Заказать» или сбой сети не создают второй заказ;
* лимиты: 5 неверных паролей → блокировка на 15 минут; не более 10 заказов в час с одного аккаунта.

## Если нужно изменить

| Что | Где менять |
|---|---|
| Промокоды (`VB5`, `SKFU`) | `CONFIG.PROMO_CODES` здесь **и** `src/lib/promo.ts` на сайте |
| Пункты выдачи, службы доставки | `CONFIG.PICKUP_POINTS` / `COD_PICKUP_POINTS` / `DELIVERY_SERVICES` здесь **и** `src/lib/delivery.ts` |
| Стоимость доставки | `CONFIG.DELIVERY_PRICES` здесь **и** `RUSSIA_SERVICE_PRICES` в `src/lib/delivery.ts` |
| Имя листа с заказами / пользователями | `CONFIG.ORDERS_SHEET` / `USERS_SHEET` (точно, включая регистр) |
| Начальные статусы | `CONFIG.STATUS_PREPAID` / `STATUS_ON_RECEIPT` |
| С какого номера начинать нумерацию | `CONFIG.ORDER_NUMBER_START` |

После правки скрипта не забудьте **опубликовать новую версию** (шаг 3, пункт 3).

## Что важно знать

* **Остатки не списываются автоматически.** Заказ не меняет остатки в вашем каталоге — вы подтверждаете
  заказ и обновляете остатки как обычно (так же, как с прежними заявками). Сервер лишь не примет заказ
  на размер, которого уже нет, или на большее количество, чем есть.
* **Нет восстановления пароля** (для него нужна SMS). Если покупатель забыл пароль — удалите его строку на
  листе USERS, и он сможет зарегистрироваться заново с тем же номером.
* Онлайн-оплаты и автоматической передачи заказов в службы доставки нет — выбранная служба и пункт
  выдачи записываются в заказ, дальше вы оформляете отправку сами.

## Автотесты серверной части

Тесты запускают **настоящий** `VBStoreApi.gs` в Node.js с имитацией сервисов Google:

```bash
node --test apps-script/tests/backend.test.mjs
```

Проверяют регистрацию/вход (пароль не хранится), токены, создание заказов (ПВЗ/службы, «При получении»,
промокод, остатки, подмену суммы, дубли), историю заказов и совместимость с существующим скриптом.
Каталог для тестов — `apps-script/tests/fixtures/catalog.sample.json` (первые строки — реальные данные
магазина, строки TEST — искусственные граничные случаи).
